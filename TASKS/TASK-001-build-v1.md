TASK-001 — Website Demo Business V1

1. PROJECT CONTEXT

We are building a small, phone-operated website business.

The owner is operating primarily from an Android phone and wants to acquire customers through Facebook and other social platforms.

The business model is deliberately simple:

«Build professional, mobile-friendly websites for small businesses and entrepreneurs starting at $20.»

The website-demo project is both:

1. A real business website used to acquire website customers.
2. A demonstration/portfolio system containing live demo websites that prospects can open and test before purchasing.

The goal is NOT to build a generic website template repository.

The goal is to create a production-ready V1 sales system that can actually be published and used to acquire the first paying customer.

---

2. PRIMARY BUSINESS OBJECTIVE

The immediate objective is:

«Help the owner obtain the first paying website customer.»

The system should therefore prioritize:

- Clear offer
- Strong live demonstrations
- Mobile-first experience
- Simple ordering
- Simple payment
- WhatsApp communication
- Fast customer conversion
- Fast delivery
- Easy future customization

Do not over-engineer the application.

Do not build unnecessary SaaS features.

Do not create features simply because they are technically interesting.

Every feature must support:

- acquiring customers
- converting customers
- collecting customer information
- receiving payment
- delivering websites
- managing the website-building workflow

---

3. TARGET CUSTOMERS

The initial target market is African small businesses and entrepreneurs.

Primary acquisition channels:

- Facebook
- Facebook groups
- Instagram
- WhatsApp
- Other social platforms

Important markets:

- Nigeria
- Other African countries
- African entrepreneurs internationally

The website must support both Nigerian and international prospects.

Do not make the site appear Nigeria-only.

4. CORE OFFER

12. DESIGN DIRECTION

The entire system should look like a legitimate professional web-design business.

Avoid:

- Generic AI-looking layouts
- Excessive gradients
- Excessive animations
- Clutter
- Huge blocks of text
- Unnecessary 3D effects
- Slow-loading visual effects
- Template-like appearance

Prioritize:

- Strong typography
- Clear hierarchy
- Good spacing
- Excellent mobile layout
- High-quality imagery
- Strong CTA placement
- Professional cards
- Consistent design system
- Fast loading

The main website should look trustworthy enough that a business owner would be comfortable paying for the service.

---

13. MOBILE-FIRST REQUIREMENT

This is extremely important.

The owner operates from Android.

Customers will also frequently view the site from mobile phones.

Therefore:

- Design mobile-first
- Test small screens
- Buttons must be easy to tap
- Forms must work comfortably on mobile
- Navigation must be mobile-friendly
- No horizontal scrolling
- Images must resize correctly
- Text must remain readable
- CTA buttons must be obvious
- WhatsApp links must work on mobile

Do not optimize only for desktop.

15. FORM VALIDATION

Required fields must be validated.

Do not allow obviously invalid submissions.

Validate:

- Required fields
- Email format where email is provided
- URLs where applicable
- Phone/WhatsApp field
- Reasonable text lengths

Show clear validation errors.

Never silently discard customer input.

---

16. PAYMENT FLOW

The system must support a payment step after the customer submits the required information.

The implementation should be designed so that the payment provider can be configured without rewriting the entire application.

Payment provider credentials MUST NOT be placed directly in client-side source code.

Use environment variables for secrets.

Do not expose secret keys in frontend JavaScript.

If real payment integration cannot be safely completed without credentials, implement a clean payment-ready architecture and document exactly what environment variables/configuration are required.

Do not invent payment success.

The application must not mark an order as paid merely because a user clicks a button.
